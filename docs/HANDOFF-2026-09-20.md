## 1. The project in four sentences

`braille-ocr` is an Android app that photographs printed pages and reads them out as
speech and as braille cells on an ESP32-driven 16-cell pad. The recognition pipeline is
ML Kit (primary, bundled, closed) and Tesseract (second reader), then `ocr-core`'s
structuring stages, then an offline spell-correction layer that votes the two recognizers
against each other, then an optional online Gemini pass. The user is preparing it for a
competition where AI integration is heavily weighted. The working language of the corpus
is Indonesian.

## 2. The single most important finding — and what has been done about it

**Most of the app's word error was word *ordering*, not recognition.** Root cause:
`OcrEngine` passes rotation into `InputImage.fromBitmap(scaled, rotation)`, so ML Kit
returns word boxes already upright. It groups words into a "line" by baseline proximity,
and on a curved page words at different x sit at different y, so it **chains across the
curve**. The scramble is *inside one line's own `text`*, and all ten structuring stages
operate on whole lines, so none of them can repair it.

**This is now fixed and on by default.** `WordRowRebuilder` re-derives printed rows from
word boxes before any other stage runs, gated so it only touches pages that actually show
the defect.

| Measurement (14 pages, 15,597 ref chars) | Before | After |
| --- | --- | --- |
| Corpus CER | 18.49% | **15.44%** |
| Corpus WER | 28.38% | **25.07%** |
| `20260731_230858` | 23.16% | **0.74%** |
| `20260919_223954` (the spread that used to break) | 38.76% | **37.09%** |
| `20260919_224138` | 2.36% | **0.74%** |
| pages improved / unchanged / worse | — | **3 / 11 / 0** |

The 11 unchanged pages are **byte-identical** to the baseline dump. That is the control:
the gate provably touched only the pages it claimed to.

**What unblocked it** (this was the whole difficulty): rebuilding rows destroys the "short
line at the frame edge" signal `FrameEdgeFragmentFilter` uses to reject an intruding facing
page. The fix is `FrameEdgeFragmentFilter.edgeWords(...)`, which makes the same judgement
on **words**, before any regrouping, so it no longer depends on a grouping we are about to
replace. Rejected words never enter the pool rows are built from.

## 4. What was tried this session and rejected — with evidence

1. **`crossChainMinIntruders = 1`** (the gate currently needs 2 intruding words in one
   intra-line gap). Measured: improves `20260919_222813` by 4.84 pp and `20260919_222952`
   by 2.13 pp, **no page worse**. Rejected anyway: it breaks
   `an open book's facing page is discarded, not read as a second column`, one of the seven
   tests the plan forbids re-baselining. On `real-facing-page-231108-raw.json` the gate then
   fires, and *that* page's facing surface is rejected by **angle**, not frame-edge
   geometry — rebuilding changes the angles. **Do not retry this without solving the angle
   interaction first.**
2. **Gemini constrained reordering.** Written, then reverted: the free-tier quota died
   mid-measurement. Relaxing a fabrication guard unmeasured is not acceptable for a reader
   who cannot see the page. The tooling to finish it is in place — see §6.

Still rejected from the previous session: rebuild unconditionally; one global left-to-right
pass; rebuild after the facing-page filters; surgical rebuild of only cross-chained lines;
gating on a raw gap threshold.

## 6. What to do next

### Priority 1 — Task 8: human-verify 25 transcripts. **This needs the user, not Claude.**

All 37 transcripts are `AI_TRANSCRIBED`. Every absolute accuracy figure is AI-vs-AI.
An AI "verifying" them produces another AI transcript wearing a `HUMAN_CORRECTED` label,
which is worse than leaving it undone — it launders the provenance and makes every
downstream number falsely defensible. **Do not do this task yourself.** Set it up for the
user: pick the 25 pages, open each `<id>.jpg` beside `<id>.txt`, and apply the conventions
in the plan's Task 8 (main page only; reading order as a person reads it; keep printed
typos; join hyphenated line breaks; contents pages keep entry text and page number, drop
the leaders).

Note the deltas in §2 survive this — before and after are scored against the *same*
reference, so a flawed reference largely cancels. It is the **absolute levels** that are
not defensible.

### Priority 2 — Task 7: finish the Gemini reordering experiment when quota resets.

`tools/ocr_eval/gemini_eval.py --reorder` now runs the variant prompt, and every page is
scored **through the app's own `MAX_CHANGE_RATIO` guard** plus a word-multiset drift column.
Use the `CER app` column, not `CER +Gemini`: the guard rejects any block whose correction
rewrites >35% of its characters, and reordering a scrambled sentence routinely exceeds
that, so the raw number can overstate the app-level benefit to the point of meaninglessness.
Ship only if guarded corpus CER improves **and** no page's drift exceeds 5%.
The exact prompt text to re-apply is in `docs/accuracy-and-training-report-2026-09-20.md` §4.6.1.

### Priority 3 — the pages the gate still declines.

Remaining corpus error sits almost entirely on pages the gate does not fire on:

| Page | max intruders | ordering share of WER |
| --- | --- | --- |
| `20260919_222813` | 1 | 70% |
| `20260919_222952` | 1 | 81% |

`IMG_5720` is the interesting one: every adjacent word pair overlaps horizontally, so the
gap-based gate is structurally blind to it. Whatever is wrong there is not cross-chaining
as this stage defines it. Diagnose before coding.

## 7. Environment — these cost hours, they will cost you hours too

| Trap | What to do |
| --- | --- |
| System Java is 26; Gradle fails with a bare `26.0.1` | `JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"` (JBR 21) |
| `./gradlew connectedAndroidTest` **uninstalls** the APK afterwards, deleting your results | Use `adb shell am instrument` |
| **Git Bash rewrites `/sdcard/...` into a Windows path**, so `adb push` silently lands files in `/sdcard/C:/Program Files/...` | `export MSYS_NO_PATHCONV=1`, and give the *source* as `C:/Users/...` not `/c/Users/...` |
| **Instrumented harnesses cannot read `/sdcard/Download/`** (scoped storage) — they report "no corpus images found" and still exit `OK` | Push into `/storage/emulated/0/Android/media/id.dotcode.braille.ocr.mlkit.test/<dir>` and pass it via `-e brailleSamplesDir` / `-e brailleCorpusDir` |
| Emulator at `hw.ramSize=2048` crashes instrumentation | Set 4096 in `~/.android/avd/Pixel_10_Pro.avd/config.ini` |
| `lstmeval` list files must use **LF** | `open(p, "w", newline="\n")` |
| A custom `TESSDATA_PREFIX` dir needs `configs/` copied in | Else `tsv` / `lstm.train` are silently ignored |
| `TesseractReader.DATA_VERSION` gates the bundled-model copy | Bump it or a model swap silently does nothing |
| Harness reports a number even when it only found the 4 bundled seeds | **Always check the scored-page count** |
| **A crashed `gemini_eval.py` run still burns the daily quota.** One crash cost the whole Task 7 measurement. | Dry-run the scoring path on an existing results file before spending requests |

### Two techniques worth reusing

- **`OcrBatchRawDumpHarnessTest` reproduces committed fixtures byte-for-byte.** Re-dumping
  `20260731_230858.jpg` regenerated `real-curved-230858-raw.json` exactly. Use that as a
  self-check before trusting a newly captured fixture.
- **The JVM structurer reproduces the device's `raw_cer` to four decimals.** So a config
  sweep can be run as a plain `:ocr-core:test` against `artifacts/raw-dumps/*.json` in
  seconds, instead of a ~5-minute device cycle per arm. That is how the
  `crossChainMinIntruders` sweep in §4 was done.
